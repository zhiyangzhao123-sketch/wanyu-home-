周末我在《科技爱好者周刊》里看到一个装进浏览器的小东西，叫 Overgrown。它会让久没打开的网页慢慢长满藤蔓，等你回来，得用鼠标一根一根砍掉，才看得见下面的字。

我装来玩了两遍，觉得有点治愈。然后冒出一个很幼稚的念头：能不能让它长得快一点。

于是我这辈子第一次点开一个 GitHub 仓库。文件夹一个套一个，大部分看不懂。README 读了半页就放弃，什么依赖、什么构建，每个字都认得，连在一起就不知道在讲什么。

我不信邪，在文件里搜「vine」。翻到第三个的时候，看见一个数字，旁边像是写着生长速度。我把它改大，存下来，刷新页面。

藤蔓几乎是瞬间就爬满了整个屏幕。

我坐在椅子上愣了几秒。这不是我写的程序，我连它怎么跑起来的都不知道；可我改了它，它就照着我改的样子动了。很难形容那种感觉，有点像小时候第一次拧开收音机的后盖。

后来我又把它改回去了，因为长太快就不好看了。

关电脑前，我去阳台看了一眼真的植物。它长了一个月，才爬过栏杆一点点。

## 这个插件怎么用

它叫 Overgrown，装进浏览器就能用，什么都不用设置。你离开一个页面久了，它自己慢慢长出藤蔓；回来的时候，用鼠标划过藤蔓，一根一根砍断，才看得见底下的网页。

它没有开关，也没有设置面板，不喜欢只能卸掉。所以我把它装在一个平时不怎么用的浏览器上。

## 什么时候可以改，什么时候不行

我改的是别人的代码。技术上没有门槛，但这不等于没有边界。

每个开源仓库里通常会有一个 LICENSE 文件，它的名字基本就决定了你能做什么：

- **MIT、Apache 2.0**——随你改、随你用，商业用也行，只要保留原作者的版权声明。
- **GPL 一类**——你也能改，但如果你把改过的版本**再发布出去**（不是自己用），你得把源码一起公开，并且沿用同一个许可证。

自己改着自己玩，几乎不会碰到问题。麻烦都出现在「分发」那一刻：打包进自己的产品、发给同事、传到网上。

所以我现在会先扫一眼仓库根目录有没有 LICENSE，再决定这个改动是留给自己，还是能拿出去。那天我改的那个数字，最后只是留在自己电脑上，谁也没影响。

## 今天学到的

- 一个仓库读不懂是正常的，别从第一行开始读，先找那个「能动的数字」。
- 改一个参数，比从零写起更容易让人相信「这个东西我能碰」。
- 改完要记得能改回去，不然下次就不敢再动了。
- 改别人的东西之前，先看一眼它允许你改到什么程度。
